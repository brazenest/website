# design-sync notes

## Shape: tokens-only (off-script)

This repo is **not** a React component design system — it's an Astro static
front-end + Payload CMS website (`package.json`: "Payload CMS … + Astro static
front-end"). The `/design-sync` converter is built for bundlable React
component libraries (Storybook or a compiled `dist/`); there is nothing here it
can bundle:

- Components are `.astro` single-file components (server-rendered HTML/CSS), not
  React — they can't render in the Claude Design React runtime.
- No Storybook, no `*.stories.*`, no component `dist/` exporting a global.

So on 2026-07-24 we synced **tokens only** (user's explicit choice), by hand:

- Source of truth for tokens: `astro/src/styles/engine.css` (the grammar) +
  `astro/src/styles/venture-tokens.generated.css` (per-venture palettes,
  auto-generated by `pnpm run export` from the Payload `ventures` collection).
- Fonts: `astro/public/fonts/*.woff2` (10 files).
- Built bundle: `ds-bundle/` → `styles.css` (@imports fonts + tokens),
  `tokens/tokens.css`, `fonts/fonts.css` + woff2, `README.md` (conventions).
- No `_ds_sync.json` anchor written (off-script; the storybook/package hash
  recipes don't apply). A re-sync therefore re-verifies from scratch — correct.

## Re-syncing

Re-run by rebuilding `ds-bundle/` from the two source CSS files above whenever
tokens change. The venture palettes regenerate via `pnpm run export`, so
`venture-tokens.generated.css` is the file to re-copy. `README.md` /
`tokens/tokens.css` header grammar is hand-authored — update it only if the
`data-work` / `data-mode` / zone axes change.

If a real React component library is ever built for this site, switch `shape`
in config.json and use the normal converter instead.
